# Cloudflare WARP Pre-Installation Auditor

## Overview

This PowerShell script is a **non-interactive diagnostic tool** designed to verify if a Windows machine meets the specific environmental requirements for a successful Cloudflare WARP installation.

The audit criteria are derived from a comprehensive file and registry access log analysis of the Cloudflare WARP installer. It captures potential "Access Denied" events and system conflicts without interrupting the script execution, providing a gap analysis of what may cause an installation to fail.

---

## Key Features

* **Non-Remediating**: The script only reports findings; it does not change system settings, modify the registry, or kill processes.
* **Robust Error Handling**: Every check is wrapped in try/catch blocks to capture and report permission denials that would normally terminate a standard script.
* **Architecture Sensitivity**: Identifies ARM64-specific requirements (like xtacache) and checks for architecture-specific driver issues.
* **Service Lifecycle Logic**: Specifically recognizes that msiserver is often stopped by default and marks it as a PASS as long as it is not Disabled.

---

## How to Use

### 1. Prerequisites

* **PowerShell 5.1 or higher**.
* **Execution Policy**: Must allow script execution. You can run this for the current session:
**Set-ExecutionPolicy RemoteSigned -Scope Process**

### 2. Running the Script

To get the most accurate results, run the script in two different contexts:

1. **Standard User**: To identify what permissions a typical user profile lacks.
2. **Administrator**: To verify that the underlying system environment is healthy even when full privileges are granted.

**Command:**
**.\permissions_audit.ps1**

## Component Importance & Impact Analysis

Based on the Cloudflare WARP audit log, the following checks are essential for functionality:

**Wintun Driver**

* **Importance**: High
* **Rationale**: Deploys wintun.dll for virtual networking.
* **Impact of Failure**: Conflicting versions from other VPNs (WireGuard/OpenVPN) can cause adapter failure or OS crashes.

**msiserver (Windows Installer)**

* **Importance**: Critical
* **Rationale**: Manages the MSI database and the C:\Windows\Installer cache.
* **Impact of Failure**: If set to Disabled, the installer cannot extract binaries or register the product. Manual/Stopped is the correct default state.

**BFE (Base Filtering Engine)**

* **Importance**: High
* **Rationale**: Injects inbound firewall rules for warp-svc.exe.
* **Impact of Failure**: Without BFE, the app traffic will be blocked by Windows Firewall by default.

**Dnscache (DNS Client)**

* **Importance**: High
* **Rationale**: Handles local DNS resolution and system-wide handoffs.
* **Impact of Failure**: Malfunctioning service leads to the app showing "Connected" but having no internet access.

**WlanSvc (WLAN AutoConfig)**

* **Importance**: Dependency
* **Rationale**: CloudflareWARP is explicitly configured to depend on this service.
* **Impact of Failure**: If disabled, the WARP background daemon will refuse to start.

**Port 53 (DNS)**

* **Importance**: High
* **Rationale**: Used for local DNS proxying via cfwarp_daemon_dns.txt.
* **Impact of Failure**: If occupied, the encrypted DNS features will fail, leading to DNS leakage.

**Port 2408 (WARP)**

* **Importance**: Critical
* **Rationale**: Primary tunnel port for the WireGuard/WARP protocol.
* **Impact of Failure**: If this port is used by another app, the VPN will remain stuck at "Connecting" indefinitely.

## Technical Findings from Audit

**Symbolic Links**
The directory C:\Users\All Users is a symbolic link to C:\ProgramData. This script verifies access to the link itself to ensure Group Policies aren't blocking legacy path resolution used by the installer.

**Registry HKLM**
The installer modifies HKLM\SYSTEM\CurrentControlSet\Services\CloudflareWARP. Write access to the Services hive is mandatory for the background daemon to exist and be managed by the Service Control Manager.

**ARM64 Translation**
On ARM-based devices (e.g., Snapdragon), the installer utilizes C:\Windows\xtacache. Denied access here prevents the binary translation required for x64 components to run with native-like performance.
